# Development rules

- The user is the project lead and approves all decisions.
- Do not implement unrequested functionality.
- Do not assume missing requirements or silently choose between meaningful alternatives.
- Ask for clarification when a decision is necessary.
- Prefer simple, maintainable solutions.
- Do not add dependencies, abstractions, or infrastructure without a demonstrated need.
- Explain significant technical decisions before implementing them.
- Scope changes strictly to the approved task.
- Run appropriate checks before reporting completion.
- Report completed work, commit hashes, blockers, and outstanding decisions.
